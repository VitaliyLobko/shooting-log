# Shooting Log — учёт БК и настрела

Веб-приложение (PWA) для телефона и компьютера: боеприпасы, покупки, списание на
стрельбах, настрел по каждому стволу и рецепты самоснаряжения. Работает без
интернета, ставится на главный экран Android как обычное приложение, данные
синхронизируются через ваш Google Диск.

**Открыть:** https://vitaliylobko.github.io/shooting-log/ (GitHub Pages, публикуется
из ветки `main`).

## Установка на телефон

1. Открыть ссылку выше в Chrome на Android.
2. Меню ⋮ → «Установить приложение» (или «Добавить на главный экран»).
3. **Ещё → Подключить Google Диск** — один раз на каждом устройстве.

## Как пользоваться

| Экран | Действие |
|---|---|
| **БК** | свайп карточки патрона **вправо** — покупка, **влево** — списание на стрельбу (с выбором ствола); тап — история, пересчёт, правка |
| **Оружие** | настрел, ресурс ствола, счётчик «после чистки»; свайп **влево** — записать стрельбу; кнопка «Почистил» сбрасывает счётчик чистки |
| **Журнал** | все движения по дням, фильтры, итог настрела по калибрам; тап — удалить запись |
| **Рецепты** | компоненты (свайп вправо — купить) и рецепты с себестоимостью; свайп рецепта вправо — «снарядил N шт»: компоненты списываются, патроны приходят в БК |
| **Ещё** | синхронизация, резервная копия, импорт |

После любого действия внизу появляется «Отменить».

## Данные и синхронизация

- Всё сначала пишется на устройство (IndexedDB), поэтому на полигоне без связи
  приложение работает как обычно.
- При подключённом Google Диске данные лежат в файле `shooting-log.json` на
  **вашем** Диске. Синхронизация идёт при открытии приложения, после каждого
  изменения и при появлении сети; индикатор `☁` в шапке показывает состояние.
- Доступ — scope `drive.file`: приложение видит только свой файл, остальной Диск
  ему недоступен. В репозитории ваших данных нет.
- Слияние по `id`: побеждает запись с более поздним `updated`; удаления
  оставляют «надгробок» (`tombstones`), поэтому записи, сделанные офлайн на
  двух устройствах, не затирают друг друга.
- Резервный файл можно сохранить вручную: **Ещё → «Поделиться копией»**.

## Как устроен учёт

Остатки и настрел нигде не хранятся числом — они всегда считаются из журнала
движений, поэтому не расходятся и любую ошибку видно в истории.

- `movements` — каждое движение: `kind` (`buy` покупка, `shot` стрельба,
  `reload` снаряжение, `consume` расход компонента, `adjust` корректировка),
  `qty` со знаком, ссылки на патрон / компонент / оружие.
- Стрельба без патрона (`cartridgeId` пуст) — историческая запись: идёт в
  настрел, но не уменьшает БК.
- Гильзы при снаряжении не списываются — они многоразовые.

## Настройка Google Диска (один раз)

В [Google Cloud Console](https://console.cloud.google.com/):

1. Создать проект `shooting-log`.
2. **APIs & Services → Library → Google Drive API → Enable.**
3. **Google Auth Platform → Branding / Audience**: тип *External*, статус
   *Testing*, свой Gmail — в *Test users*.
4. **Clients → Create client → Web application**, *Authorized JavaScript origins*:
   - `https://vitaliylobko.github.io`
   - `http://127.0.0.1:8091` (локальная разработка)
5. Скопировать *Client ID* в `js/config.js`.

Client ID не секрет — без входа в ваш Google-аккаунт он ничего не даёт.

## Разработка

Сборки нет — чистые HTML / CSS / JS-модули.

```sh
py -m http.server 8091 --bind 127.0.0.1
# открыть http://127.0.0.1:8091/
```

**Перед каждым релизом поднять версию в `version.js`** — по ней service worker
понимает, что пора обновить кэш. Без этого телефон продолжит показывать старую
версию. После пуша в `main` GitHub Pages обновится за 1–2 минуты, а в
приложении появится плашка «Доступна новая версия → Обновить».

| Файл | Что внутри |
|---|---|
| `js/app.js` | экраны, шторки, действия |
| `js/model.js` | расчёты: остатки, настрел, себестоимость рецепта |
| `js/sync.js` | вход в Google и синхронизация с Диском |
| `js/db.js` | обёртка над IndexedDB, надгробки удалений |
| `js/ui.js` | элементы, шторка, тост, форма, свайп |
| `js/config.js` | Google Client ID |
| `sw.js` | офлайн-кэш и обновления |
