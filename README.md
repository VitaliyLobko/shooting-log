# Shooting Log — облік БК і настрілу

Вебзастосунок (PWA) для телефона й комп'ютера: боєприпаси, покупки, списання на
стрільбах, настріл кожного ствола, фото зброї, склад компонентів і рецепти
самоспорядження. Працює без інтернету, встановлюється на головний екран Android
як звичайний застосунок, дані синхронізуються через ваш Google Диск.

Інтерфейс — українською або російською (**Ще → Мова**), тема — авто, темна або
світла (**Ще → Тема**).

**Відкрити:** https://vitaliylobko.github.io/shooting-log/ (GitHub Pages, публікується
з гілки `main`).

## Встановлення на телефон

1. Відкрити посилання вище в Chrome на Android.
2. Меню ⋮ → «Установити застосунок» (або «Додати на головний екран»).
3. **Ще → Підключити Google Диск** — один раз на кожному пристрої.

## Як користуватися

| Екран | Дія |
|---|---|
| **БК** | угорі — скільки набоїв усього й по кожному калібру; групи калібрів згортаються. На картці — ціна одного пострілу. Свайп картки **вправо** — покупка, **вліво** — списання на стрільбу (з вибором ствола й вартістю); тап — історія, перерахунок, правка |
| **Зброя** | фото (кілька на ствол, одне головне; редактор — кадрування, поворот на 90°, вирівнювання ±45°, дзеркало), настріл, вартість стрільб, ресурс ствола (орієнтир за калібром), приціли; свайп **вліво** — записати стрільбу, **вправо** — «почистив сьогодні». Журнал чистки, нагадування: без інтервалу — після кожної стрільби, з інтервалом — коли постріли після чистки його досягли; точка на вкладці й нагадування раз на день |
| **Журнал** | рухи, згруповані за днями, тижнями, місяцями або роками (групи згортаються, з підсумком пострілів і вартістю тренування); своя іконка для кожного типу; фільтри за типом і за зброєю, настріл за калібрами з розбивкою по стволах; тап — змінити ствол у записі стрільби або видалити запис |
| **Рецепти → Рецепти** | собівартість набою, скільки можна спорядити із запасів і який компонент закінчиться першим; свайп вправо — «спорядив N шт»: компоненти списуються, набої приходять у БК |
| **Рецепти → Склад** | компоненти за типами: залишок, сума, на скільки набоїв вистачить у кожному рецепті; позиції, що закінчуються, підсвічені; свайп вправо — купити, вліво — перерахунок |
| **Ще** | довідник стрільця, своя іконка, мова, тема, синхронізація, резервна копія, імпорт |
| **Ще → Довідник стрільця** | курс марксмана (23 теми, поки що російською): положення для стрільби, спуск, міл і MOA, пристрілка, балістика, вітер, дальність, калькулятор міл, таблиці M855 і .308, тренажер сітки DSMR / Ballistic Plex; пошук, посилання між розділами, працює офлайн |
| **Ще → Своя іконка** | будь-яка картинка з галереї, обрізана в квадрат: показується в шапці й на вкладці браузера, зберігається лише на пристрої; кнопка дає PNG 512×512 для ярлика на робочому столі (Android бере іконку встановленого застосунку із сервера, тож її ставлять через лаунчер або Shortcut Maker) |

Після будь-якої дії внизу з'являється «Скасувати».

## Дані й синхронізація

- Усе спершу пишеться на пристрій (IndexedDB), тому на полігоні без зв'язку
  застосунок працює як завжди.
- З підключеним Google Диском дані лежать у файлі `shooting-log.json` на
  **вашому** Диску, а фото — окремими файлами `shooting-log-photo-<id>.jpg`.
  Синхронізація йде під час відкриття застосунку, після кожної зміни й коли
  з'являється мережа; індикатор `☁` у шапці показує стан.
- Фото стискаються на пристрої до 1600 px (JPEG). Мініатюра (~10 КБ) їде в JSON,
  тому список зброї з фото видно одразу, а повне фото докачується на інших
  пристроях під час синхронізації.
- Доступ — scope `drive.file`: застосунок бачить лише власні файли, решта Диска
  йому недоступна. У репозиторії ваших даних немає.
- Злиття за `id`: перемагає запис із пізнішим `updated`; видалення лишають
  «надгробок» (`tombstones`), тому записи, зроблені офлайн на двох пристроях,
  не затирають одне одного. Видалене фото потрапляє в кошик Диска.
- Резервний файл можна зберегти вручну: **Ще → «Поділитися копією»**. У ньому
  лише мініатюри фото, самі фото — на Google Диску.
- Після оновлення застосунку оновіть його на **всіх** пристроях: стара версія
  не знає про фото й до оновлення не показуватиме їх.

## Як влаштований облік

Залишки й настріл ніде не зберігаються числом — вони завжди рахуються з журналу
рухів, тому не розходяться, і будь-яку помилку видно в історії.

- `movements` — кожен рух: `kind` (`buy` покупка, `shot` стрільба,
  `reload` спорядження, `consume` витрата компонента, `adjust` коригування,
  `clean` чистка ствола з `qty` 0),
  `qty` зі знаком, посилання на набій / компонент / зброю.
- Стрільба без набою (`cartridgeId` порожній) — історичний запис: іде в
  настріл, але не зменшує БК.
- Гільзи під час спорядження не списуються — вони багаторазові.
- Калібр порівнюється з урахуванням написання: `.223 Rem` = `5.56×45` = `223`,
  `.308 Win` = `7.62×51` тощо. Під час вибору ствола чи набою свої йдуть першими,
  решта — групою «Інший калібр».
- Вартість пострілу — середня ціна набою за покупками й спорядженнями з сумою
  (для самоспорядження без таких рухів — собівартість рецепта). Під час списання
  вона фіксується в `price` руху `shot`, тож пізніші покупки за іншою ціною не
  змінюють вартість минулих стрільб. Старі записи без `price` рахуються за
  поточною середньою ціною.
- «Після чистки» — постріли, записані пізніше за останню чистку (за датою, в межах
  дня — за часом запису).
- `photos` — запис фото: `weaponId`, мініатюра, `driveId` файлу на Диску.
  Відредаговане фото зберігається як нове (новий `id`), старе йде в кошик Диска.
  Сам файл фото — у локальному сховищі `blobs`, поза JSON.

## Налаштування Google Диска (один раз)

У [Google Cloud Console](https://console.cloud.google.com/):

1. Створити проєкт `shooting-log`.
2. **APIs & Services → Library → Google Drive API → Enable.**
3. **Google Auth Platform → Branding / Audience**: тип *External*, статус
   *Testing*, свій Gmail — у *Test users*.
4. **Clients → Create client → Web application**, *Authorized JavaScript origins*:
   - `https://vitaliylobko.github.io`
   - `http://127.0.0.1:8091` (локальна розробка)
5. Скопіювати *Client ID* у `js/config.js`.

Client ID не секрет — без входу у ваш Google-акаунт він нічого не дає.

## Розробка

Збірки немає — чисті HTML / CSS / JS-модулі.

```sh
py -m http.server 8091 --bind 127.0.0.1
# відкрити http://127.0.0.1:8091/
```

**Перед кожним релізом підняти версію у `version.js`** — за нею service worker
розуміє, що час оновити кеш. Без цього телефон і далі показуватиме стару
версію. Новий JS-файл треба також додати до списку `ASSETS` у `sw.js`. Після
пушу в `main` GitHub Pages оновиться за 1–2 хвилини, а в застосунку з'явиться
плашка «Доступна нова версія → Оновити».

Тексти інтерфейсу: ключ — російський рядок у коді (`t('…')`), переклад — у
словнику `UK` в `js/i18n.js`. Рядка без перекладу в консолі видно як
`i18n: немає перекладу`.

| Файл | Що всередині |
|---|---|
| `js/app.js` | екрани, шторки, дії |
| `js/model.js` | розрахунки: залишки, настріл, собівартість рецепта, склад |
| `js/photos.js` | стиснення фото й перегляд на весь екран |
| `js/i18n.js` | мова інтерфейсу й український словник |
| `js/sync.js` | вхід у Google й синхронізація з Диском (дані та фото) |
| `js/db.js` | обгортка над IndexedDB, надгробки видалень, файли фото |
| `js/ui.js` | елементи, шторка, тост, форма, свайп, формат чисел |
| `js/config.js` | Google Client ID |
| `sw.js` | офлайн-кеш і оновлення |
